## Source of truth
**`src/config/site.ts` holds every brand fact** — name, wordmark halves, tagline, origin,
email, phone, advisor, address, hours, service area. Pull from it; never retype a value
into a page. `scripts/audit.mjs` fails the build if the built site renders more than one
distinct phone string, which is the guard rail that catches a hand-typed number.

Two contact addresses, and they are not interchangeable:
- `site.email` → **hello@602medicare.com**, the practice inbox. Footer NAP, contact card,
  legal pages, the Organization node, the lead form's mailto fallback.
- `site.agent.email` → **brian@602medicare.com**, Brian direct. The Person node and one
  line on `/contact/`. Do not spread it further.

Other data files, each the only place its subject lives:
`src/data/medicare-figures.ts` (**every CY dollar figure** — annual update due mid-November)
· `src/data/locations.ts` (cities, counties, ZIPs) · `src/data/compliance.ts` (TPMO,
non-affiliation, NPN line) · `src/data/products.ts` · `src/data/faqs.ts` ·
`src/data/tools.ts` · `src/data/enrollment.ts` · `src/data/testimonials.ts`.

## Dollar figures are tokens, not digits
Markdown articles write `{{partB.premium}}`, `{{partA.deductible}}`, `{{partD.cap}}`,
`{{irmaa.singleStart}}`, `{{year}}` … and `plugins/remark-medicare-figures.mjs` substitutes
them at build time from `medicare-figures.ts`. The full map is `FIGURE_TOKENS` in that
plugin. **An unknown token throws at build time on purpose** — a silently wrong dollar
figure on a Medicare site is the failure this arrangement exists to prevent. Use a token
wherever one exists.

## Two content shelves — do not confuse them
- **`src/content/learn/`** — the evergreen reference shelf. Long explainers, revised in
  place when CMS moves a number.
- **`src/pages/blog/`** — dated, local, seasonal: this market, this plan year, this
  deadline. A plain `.md` file with `layout: ../../layouts/BlogLayout.astro` is the whole
  publishing act — the hub globs it and the route, JSON-LD and sitemap entry follow. There
  is no posts array to update (that is the Medicare On Main repo's arrangement, not this
  one).

The header comment in `src/layouts/BlogLayout.astro` is the authority on the split.

**Featured images are generated, not stock:**
`node scripts/build-blog-card.mjs <name> "<kicker>" "<title>"` → `public/blog/<name>.png`
at 1200×630, serving as both in-article image and social card. Needs Chrome and network
(Google Fonts). **Always a new filename** — `public/_headers` caches `/*.png` for seven
days, so overwriting a card keeps serving the stale one from the edge.

## Schema
Centralised in `src/components/Schema.astro` and the layouts. **Never hand-roll JSON-LD in
a page.** BlogPosting + FAQPage + BreadcrumbList come from blog frontmatter;
InsuranceAgency/LocalBusiness + Person come from `site.ts`.
`/llms.txt` is generated by `src/pages/llms.txt.ts` and is excluded from the sitemap (the
audit requires every sitemap URL to have an HTML route). There is no WebMCP endpoint here.

## Compliance (Medicare — mandatory)
- The TPMO disclaimer and non-affiliation line come from `src/data/compliance.ts` and
  render **exactly once per page, in the footer**. The audit fails the build on a second
  copy — so do **not** add one to article bodies.
- Wording follows the **CY2027 final rule: no SHIP reference.** Never re-add "or your State
  Health Insurance Assistance Program".
- No carrier names as endorsements; no banned superlatives (best, #1, cheapest,
  top-rated); never call a $0-premium plan "free"; no implied CMS or government
  endorsement; TCPA consent on call/text CTAs; education, not advice.
- **No ACA / marketplace content.** The practice does not sell it.
- Beyond Medicare the practice does sell long-term care, dental-vision-hearing,
  cancer/heart-attack/stroke, hospital indemnity, short-term home health and final
  expense, plus a retirement-income and Social Security division for households with
  $250k+ investable assets. The services grid shows four cards because the others have no
  pages yet — copy around it must say those four are where conversations *start*, not
  where the practice ends. **Never restate "we only sell Medicare".**
- LTC, annuity and life-adjacent copy is education only: no rates, returns, premiums,
  carrier or product names; refer to a licensed professional, and to a tax advisor for
  Roth-conversion and IRMAA-appeal questions.

## Build, verify, deploy
```bash
npm install
npm run dev        # http://localhost:4321
npm run verify     # astro check → unit tests → build → audit. The gate. Must pass.
npm run e2e        # dependency-free CDP suite (461 checks)
```
- `npm run verify` must end "✅ All checks passed." Never weaken an audit rule to make a
  page pass.
- Leak guard, must be 0:
  `grep -rEl 'netlify\.app|vercel\.app|workers\.dev|pages\.dev|localhost' dist | wc -l`
- Canonicals must be `https://602medicare.com/…`, never `*.pages.dev`.
- ⚠️ **`npm run e2e` is broken on `main` as of 2026-08-08** — it aborts at the home-page
  motion-engine check ("caustics canvas has painted pixels") before reaching anything
  else, and fails identically on a clean checkout. A failure at that first check is
  pre-existing; a failure anywhere else is yours.
- Screenshot gotcha: Chrome's `--window-size` does not reach CDP-created targets in new
  headless, so a mobile-width `--screenshot` crops a desktop layout instead of reflowing
  it. Use `Emulation.setDeviceMetricsOverride`, as `scripts/e2e.mjs` does, and pass
  `--force-prefers-reduced-motion` or the reveal animations are caught mid-flight.

## Brand assets
Navy `#011459` + red `#D10A0F`, and **one rule: `--red` is only 3.0:1 on navy** — anything
red on a navy ground uses `--red-lift #FF5A5F`. The badge PNG is transparent inside its
ring, so every navy placement puts it on a white disc. Full reasoning in the repo's design
tokens; `favicon.ico` is generated by `scripts/build-favicon-ico.py`, the OG card by
`node scripts/build-og.mjs` (the brand name is baked into its pixels, so a rename means a
re-render, not a find-and-replace).
